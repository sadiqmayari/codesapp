Moving CodesApp to its own VPS

Why we moved, what changed, and what every new piece does — in plain English.

1 · Why we moved

🏚️ Old home — Hostinger “Business” shared cramped

App + database squeezed onto a shared machine with other customers.
Only 1 database connection allowed at a time — the whole app queued behind a single door.
Capped CPU/RAM. A traffic spike → the host killed & restarted the app → the 503 errors & “Reconnecting…”.

We’d been writing clever code just to survive that single door. The fix isn’t more code — it’s a bigger house.

🏡 New home — your own VPS room to breathe

A dedicated server: 2 CPUs, 8 GB RAM, 90 GB disk — only your stuff.
Many database connections (a “pool” of 12) — requests run side-by-side, not single-file.
We control everything: the database, the process, the front door. No surprise restarts.

It already runs your n8n — so the #1 rule was: don’t disturb n8n.

2 · The big idea: containers sharing one front door

Instead of installing things loosely on the server (which could clash with n8n), we put our app in its own sealed container and let n8n’s existing Traefik (the “receptionist”) send visitors to it — just by adding a name tag.

4 · What each new word means

Container
A sealed box holding the app + the exact versions of everything it needs. Runs the same anywhere.
Image
The “recipe + ingredients” a container is started from. We built codesapp-app:latest once; containers start from it.
Docker Compose
A small file (docker-compose.yml) describing which containers to run together (app + database) and how they connect.
Traefik
The front-door traffic cop on ports 80/443. Reads a container’s “labels” and routes each domain to the right container, handing out HTTPS certificates automatically.
MariaDB
The database (same engine Hostinger used). We copied all your data into our own copy of it.
Connection pool
A set of reusable open database doors (we set 12). More doors = more requests served at once = no more single-file queue.
Swap
Emergency overflow memory on disk (we added 3 GB). Stops a brief memory spike from crashing anything.
Volume
A storage drawer that survives container restarts — that’s where the database files live, so data is never lost on redeploy.
Network (n8n_default)
A private wire connecting containers. Our app joined n8n’s wire only so Traefik could reach it — joining ≠ changing n8n.

5 · How we did it (repeatable for any future app)

  1. Add swap (safety net) — fallocate a swapfile.
  2. Write a Dockerfile (build recipe) + docker-compose.yml (app + database).
  3. Copy the code to the server & docker build the image.
  4. Put secrets in a .env file; start the database container.
  5. Export the old database → import into the new MariaDB.
  6. Add Traefik labels (domain name tag) → docker compose up -d.
  7. Test on a free temp address first; flip the real domain only when happy.

Golden rule we followed: build the new home and test it while the old one keeps serving customers — then switch the sign on the door last.
